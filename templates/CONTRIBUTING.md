# Contributing

## Development workflow

1. Create or select an issue.
2. Create a focused branch.
3. Implement the change.
4. Add or update tests.
5. Update documentation.
6. Run local quality checks.
7. Open a pull request.

## Branch naming

- `feat/<name>`
- `fix/<name>`
- `security/<name>`
- `refactor/<name>`
- `docs/<name>`
- `chore/<name>`

## Commits

Use Conventional Commit style.

Examples:

- `feat: add JSON export`
- `fix: handle missing configuration`
- `docs: update installation guide`

## Pull requests

Pull requests should be focused, testable, and explain why the change exists.

Do not include unrelated refactors unless required by the change.
